# Исторические посты Telegram

Здесь описана короткая лента на главной. Полный архив канала собирается отдельно, см. [Журнал Telegram](./telegram-journal.md).

Новые посты канала `@gattavasis` поступают через webhook в Cloudflare Worker. Для уже опубликованных постов служит отдельный Build target: он читает историю канала от имени пользователя Telegram и дополняет статический файл `content/telegram/posts.json`. В оба источника попадают только посты со ссылкой на `pianikova.com` или `www.pianikova.com`.

## Получить данные для входа

1. Открыть [my.telegram.org](https://my.telegram.org/) и ввести номер **своего пользовательского аккаунта** в международном формате, например `+7...`. Код для входа на сайт придёт в Telegram, а не по SMS.
2. После входа открыть **API development tools**. Если приложения ещё нет, заполнить форму его создания по [инструкции Telegram](https://core.telegram.org/api/obtaining_api_id).
3. На странице приложения найти `api_id` (число) и `api_hash` (секретная строка). Эти значения понадобятся в консоли импорта. `api_hash` никому не отправлять и не добавлять в репозиторий.
4. Убедиться, что этот пользовательский аккаунт видит историю канала `@gattavasis`.

Токен бота для чтения старой истории не используется. Код входа на сайт `my.telegram.org` и код, который позже может запросить импорт, вводятся каждый в своём окне; они не заменяют `api_id` и `api_hash`. Если `my.telegram.org` не создаёт приложение и показывает только `ERROR`, можно использовать экспорт Telegram Desktop без API-данных.

## Запустить импорт

Из корня репозитория в интерактивном терминале:

```powershell
dotnet run --project build -- telegram-history
```

В Rider выберите конфигурацию **Import Telegram history** и нажмите Run. Вводите даты и данные Telegram в окне **Run**; после завершения там останется итог `Scanned ...; matched ...; added ...` либо текст ошибки.

Target спросит начальную и конечную даты в формате `YYYY-MM-DD`. Обе даты включены, время считается по Москве. Затем в той же консоли нужно ввести `api_id`, `api_hash` и номер того же пользовательского аккаунта в международном формате. Если Telegram запросит код входа или пароль двухэтапной проверки, введите их там же. `api_hash`, код и пароль вводятся скрыто. За один запуск читается только история канала `@gattavasis` за выбранный период.

Если итоговая строка показывает `added 0`, проверьте выбранные даты и наличие в постах ссылок на `pianikova.com`. Если импорт сообщает об ошибке, сохраните её текст без секретов. Результат записывается в локальный `content/telegram/posts.json`; чтобы посты появились на опубликованном сайте, этот файл нужно отправить в `main`.

Сеанс Telegram сохраняется в `%LOCALAPPDATA%\Pianikova\telegram-history.session`, вне репозитория. Это позволяет не подтверждать вход кодом при каждом запуске. Для выхода из этого сеанса удалите файл и завершите сеанс приложения в настройках Telegram. Данные входа и файл сеанса не попадают в статический JSON.

Повторный импорт **только добавляет отсутствующие ID**. Существующие записи, включая отредактированные вручную `text`, `date` и `siteUrl`, остаются как есть. Если новых подходящих постов нет, файл не переписывается.

## Импорт без API-данных через Telegram Desktop

1. В [Telegram Desktop](https://desktop.telegram.org/) откройте канал `@gattavasis`. В меню **⋯** выберите **Export chat history** (экспорт истории чата). Telegram [поддерживает экспорт отдельного чата в JSON](https://telegram.org/blog/export-and-more).
2. Выберите формат **JSON** и нужный период. Для нынешней ленты медиафайлы не требуются: импорт читает только текст поста, ссылки и дату. Если включить экспорт фотографий, видео и других файлов, Telegram Desktop сохранит их рядом с JSON, но они не попадут в `content/telegram/posts.json` и не появятся на сайте. Дождитесь завершения экспорта; нужен файл `result.json`.
3. В Rider запустите **Import Telegram Desktop export** либо выполните из корня репозитория:

   ```powershell
   dotnet run --project build -- telegram-history-export
   ```

4. В консоли введите полный путь к `result.json` и даты периода в формате `YYYY-MM-DD` по Москве. Target проверит ID канала, отберёт посты со ссылкой на `pianikova.com` и дополнит тот же `content/telegram/posts.json`.

Экспорт можно сохранить в `C:\Projects\DevTeam\Pianikova.github.io\.telegram`; этот каталог исключён из Git. Файл `result.json` и медиа могут содержать личные данные, поэтому не переносите их в отслеживаемые каталоги. При повторном импорте записи с существующими ID и ваши ручные правки сохраняются. Для публикации обновлённого `content/telegram/posts.json` отправьте его в `main`.

## Ручное редактирование и публикация

Формат записи в `content/telegram/posts.json`:

```json
{
  "id": 123,
  "date": "2026-10-06T12:00:00+00:00",
  "text": "Текст для карточки",
  "url": "https://t.me/gattavasis/123",
  "siteUrl": "https://pianikova.com/"
}
```

`siteUrl` подтверждает, что пост относится к сайту. Его адрес должен вести на `pianikova.com` или `www.pianikova.com`. Поле `url` должно вести на пост с тем же ID в `@gattavasis`.

Чтобы исключить запись из ленты и не получить её повторно при следующем импорте, добавьте в неё `"hidden": true`. Это также скроет запись с тем же ID из динамического источника. Удалённую из файла запись импорт добавит снова, если она попадёт в выбранный период.

После ручного редактирования выполните проверку:

```powershell
dotnet run --project build -- content-check
```

Затем сохранить JSON в Git и отправить в `main`. Опубликованный сайт читает статический файл из GitHub и периодически обновляет ленту. Он объединяет записи с ответом Worker, убирает дубли по ID и показывает пять последних по дате публикации. При одинаковом ID запись из статического JSON имеет приоритет, чтобы ручная правка сохранилась.

Импорт не меняет сообщения в Telegram. Для ID, уже сохранённых в JSON, последующие правки в канале нужно перенести в файл вручную: статическая запись имеет приоритет над динамической.
