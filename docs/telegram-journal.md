# Журнал Telegram

Архив канала `@gattavasis` хранится в `content/telegram/journal` в виде готовых ресурсов: Markdown-выпусков, картинок WebP и индексов JSON. Приложение читает их с GitHub так же, как остальной контент, и ничего не вычисляет само.

Журнал не заменяет короткую ленту `content/telegram/posts.json` и Cloudflare Worker: свежие посты со ссылкой на `pianikova.com` по-прежнему приходят через webhook. В журнал посты попадают только после повторного экспорта.

## Обновить журнал

1. В [Telegram Desktop](https://desktop.telegram.org/) откройте канал `@gattavasis` → **⋯** → **Export chat history**. Формат **JSON**; включите фото и файлы, видео не нужны.
2. Сохраните экспорт в `C:\Projects\DevTeam\Pianikova.github.io\.telegram` (каталог исключён из Git), чтобы получился `.telegram\result.json`.
3. В Rider запустите **Build Telegram journal** либо выполните из корня репозитория:

   ```powershell
   dotnet run --project build -- telegram-journal
   ```

   Путь к другому экспорту можно передать аргументом: `telegram-journal D:\export\result.json`.

4. Проверьте изменения в `content/telegram/journal` и отправьте их в `main`.

Повторный запуск:

- добавляет выпуски только для новых сообщений и не трогает уже созданные папки, тексты и ручные правки;
- обновляет в существующих выпусках только поля, которые принадлежат Telegram: `tags` и `reactions`;
- пересобирает `index.json` и `search.json`.

Дополнительные режимы:

| Команда | Что делает |
|---|---|
| `telegram-journal --reindex` | Только пересобирает индексы после ручной правки Markdown; экспорт не нужен |
| `telegram-journal --rebuild 239,615` | Заново создаёт указанные выпуски из экспорта; ручные правки текста теряются, `rubric`, `series` и `hidden` сохраняются |
| `telegram-journal --rebuild all` | То же для всех выпусков |

`content-check` (в том числе в CI) проверяет front matter, наличие файлов и актуальность индексов. Если Markdown правили вручную и забыли пересобрать индексы, проверка подскажет команду `--reindex`.

## Что попадает в журнал

| Содержимое | Обработка |
|---|---|
| Текст и форматирование | Markdown; жирный, курсив, зачёркнутый, подчёркнутый (`++`), ссылки, упоминания, цитаты, код |
| Спойлер | `==текст=={.spoiler}` |
| Фото | `NN.webp` (до 1600 px) и `NN-480.webp`; размеры и средний цвет — в атрибутах |
| Альбом из нескольких фото | Контейнер `:::gallery` |
| Видео, видеокружки, GIF | Сами файлы не публикуются: превью-кадр со ссылкой на пост в Telegram, класс `.video` (кружки — `.video .round`) |
| Аудио | Название, исполнитель и длительность со ссылкой на пост. Файл копируется в выпуск только если ID сообщения указан в `publishedAudio` |
| Опрос | Вопрос и варианты ответа |
| Документ | Ссылка на пост в Telegram |
| Пересылки из других каналов, стикеры | Не импортируются |

## Выпуски

Telegram ограничивает длину сообщения, а альбом экспортируется как отдельные сообщения. Поэтому сообщения, опубликованные подряд с интервалом не больше двух минут, объединяются в один **выпуск**: альбом с подписью, эссе из нескольких сообщений, текст с аудиопримерами.

```text
content/telegram/journal/
  settings.json       ← рубрики, циклы, разрешённые аудиофайлы (редактируется вручную)
  index.json          ← каталог видимых выпусков (генерируется)
  search.json         ← простой текст для поиска (генерируется)
  posts/
    2025/
      239-i-barochnye-kukushki/
        index.md
        01.webp
        01-480.webp
```

Папка называется `{ID первого сообщения}-{slug заголовка}` и после создания не переименовывается.

### `index.md`

```markdown
---
id: 239
messages: [239, 240, 241]
date: "2025-03-11T13:38:33+03:00"
title: "I. Барочные кукушки"
source: "https://t.me/gattavasis/239"
tags: []
reactions: 18
rubric: ""
series: ""
hidden: false
cover: { file: "01.webp", width: 1280, height: 960, color: "#696963", lqip: "data:image/webp;base64,…" }
---

Текст выпуска…
```

| Поле | Кто ведёт | Назначение |
|---|---|---|
| `id`, `messages`, `date`, `source` | target | Идентификация; не менять |
| `title` | target, можно править | Первая короткая строка первого текста, если за ней идёт продолжение; иначе `null` |
| `tags`, `reactions` | Telegram | Обновляются при каждом запуске из экспорта |
| `rubric`, `series` | вручную | Переопределяют рубрику и цикл, найденные по тегам |
| `hidden` | вручную | `true` убирает выпуск из индексов |
| `cover` | target, можно править | Обложка для карточек; `lqip` — крошечное размытое превью |

Текст после front matter можно свободно редактировать. Одиночный перевод строки — это перенос строки, как в Telegram.

## Рубрики и циклы

Рубрики и циклы назначаются по хэштегам Telegram через словарь `settings.json`:

```json
{
  "schemaVersion": 1,
  "rubrics": [
    { "id": "stage", "title": { "ru": "Сцена", "en": "Stage" }, "tags": ["концерт", "фестиваль", "репетиция"] }
  ],
  "series": [
    { "id": "kukushki", "title": { "ru": "Кукушки в музыке" }, "tags": ["кукушки"] }
  ],
  "publishedAudio": [209]
}
```

- Выпуск получает первую рубрику и первый цикл, у которых совпал хотя бы один тег.
- Порядок глав цикла — по дате; в `index.json` цикл содержит упорядоченный список ID выпусков, отсюда «предыдущая / следующая глава».
- `rubric` или `series` во front matter важнее тегов: так можно разметить старый пост, не трогая Telegram.
- Строка, состоящая только из хэштегов, удаляется из текста; теги внутри предложения остаются в тексте.
- Чтобы разметить старые посты в самом Telegram, отредактируйте их там, сделайте новый экспорт и запустите target: теги обновятся, текст и ручные правки останутся.

После правки `settings.json` запустите `telegram-journal --reindex`.

## Как приложение использует данные

Раздел журнала: `/journal` (`Pages/JournalPage.razor`) и `/journal/{id}` (`Pages/JournalIssuePage.razor`). Ссылка «Журнал» есть в меню главной и в блоке Telegram.

- Лента, архив по годам с графиком публикаций по месяцам, «Любимое читателями», «В этот день», фильтр по рубрикам и «Открыть наугад» строятся из `index.json`.
- Поиск загружает `search.json` при первом вводе запроса.
- Выпуск загружает `posts/…/index.md` и рендерит его Markdig (`Data/Journal.cs`) с `UseAdvancedExtensions()`, `UseSoftlineBreakAsHardlineBreak()` и `UseYamlFrontMatter()`. Относительные ссылки (`01.webp`, `01.m4a`) разрешаются от папки выпуска, картинки получают `srcset` с `NN-480.webp` и средний цвет как фон-заглушку.
- `wwwroot/js/journal.js` оформляет аудио (плейлист, встроенный плеер для опубликованных записей), превью видео со ссылкой на Telegram, спойлеры, лайтбокс галерей и прогресс чтения.
