# Контент

## Структура

Настройки формата находятся в `content/settings/site.json`. Текущая версия схемы — `2`.

| Каталог или файл | Назначение |
|---|---|
| `content/site/{language}/site.json` | Главная страница, биография, репертуар, проекты, пресса и контакты |
| `content/schedule/{language}/schedule.json` | Афиша и архив концертов |
| `content/videos/{language}/videos.json` | Видеозаписи |
| `content/photos/{language}/photos.json` | Фотографии |
| `content/media/images` | Изображения |
| `content/media` | Общий каталог медиаресурсов; сейчас содержит изображения |
| `content/articles` | Зарезервировано; статьи пока не поддерживаются приложением |

Путь к медиаресурсу задаётся относительно `content`, например:

```text
media/images/julia-pianikova-hero-2026-v2.png
```

## Языковые версии

Одноимённые документы в `en` и `ru` являются переводами одного материала. Идентификаторы и системные поля должны совпадать, а отображаемые тексты могут различаться.

Интерфейсные команды, названия кнопок и системные сообщения не входят в JSON-контент: они находятся в `.resx`-ресурсах приложения.

## Markdown

Markdown поддерживается в полях с длинным текстом:

- краткая и полная биография;
- репертуар;
- описания творческих проектов;
- описания видео;
- тексты цитат для прессы.

Ссылки проектов следует добавлять непосредственно в Markdown-описание:

```markdown
[Теллур-трио в Telegram](https://t.me/tellur_trio)
```

Короткие названия, подписи и альтернативные описания изображений остаются обычным текстом. HTML внутри Markdown отключён.

## Концерты

Допустимые статусы:

- `announced`;
- `on_sale`;
- `sold_out`;
- `free`.

Дата и время хранятся в ISO 8601 со смещением, часовой пояс IANA — отдельным полем. Будущие события отображаются раньше прошедших; прошедшие автоматически попадают в архив.

## Изображения

- Использовать актуальный файл без резервных копий в `content/media/images`.
- Для карточек проектов достаточно ширины до 1600 px.
- Предпочтительно хранить фотографии в оптимизированном JPEG или WebP.
- Альтернативное описание должно передавать содержание изображения, а не повторять имя файла.
- Авторство и условия использования заполняются при их наличии.

## Проверка

```powershell
dotnet run --project build -- content-check
```

Проверяются JSON, наличие языков, согласованность системных полей и существование медиаресурсов.
