# Pianikova.github.io

Персональный сайт классической скрипачки на Blazor WebAssembly и Pure.DI.

## Локальный запуск

```powershell
dotnet run --project build -- local-web
```

Build-таргет синхронизирует `content` во временную web-папку и запускает приложение на `http://localhost:5188`. Без открытия браузера:

```powershell
dotnet run --project build -- local-web --no-browser
```

### Rider

Общие конфигурации находятся в `.run` и появляются в списке конфигураций после открытия решения:

- `Pianikova.Web` — запуск сайта; при старте через **Debug** Rider подключается к Blazor WebAssembly;
- `Build solution` — сборка всего решения;
- `Publish GitHub Pages` — создание production-каталога `artifacts/web/wwwroot`.

Перед локальной сборкой web-проект автоматически синхронизирует исходные данные из `content` в игнорируемый web-root. Дополнительный подготовительный запуск не требуется.

## Редактирование контента

Редактор — часть самого приложения, отдельный инструмент не нужен:

1. Открыть `http://localhost:5188/admin` (локально) или `https://pianikova.github.io/admin` (на живом сайте).
2. Войти через GitHub-аккаунт с правом записи в репозиторий сайта.
3. Выбрать раздел — «Главная страница», «Расписание концертов» или «Видео».
4. Внести правки (общие для языков поля показываются один раз, переводимые — отдельно для English и Русский) и нажать «Сохранить».

Правки коммитятся сразу в `main` и попадают на живой сайт немедленно (контент читается напрямую из GitHub во время работы сайта, без пересборки) — черновика или отдельного шага публикации для контента нет. Локальный запуск (`dotnet run --project build -- local-web`) использует тот же `/admin` и тот же настоящий репозиторий — отдельного песочница-режима для контента нет.

Коллекция «Статьи» пока не поддерживается ни в редакторе, ни на самом сайте (нет ни одной статьи и ни одной страницы, которая бы их показывала) — при необходимости эту функциональность стоит делать одним цельным шагом: модель данных + отображение + редактор.

### Авторизация в редакторе

Вход в `/admin` использует GitHub OAuth. Обмен кода авторизации на токен требует client secret, поэтому браузер не может сделать это напрямую — нужен OAuth-посредник. Он размещён как Cloudflare Worker в `cloudflare/decap-oauth` (инструкция по настройке — там же), адрес зашит в `GitHubAuthState` в `src/Pianikova.Web/Data/Admin/GitHubAuthState.cs`. Секрет GitHub OAuth-приложения нельзя добавлять в репозиторий — он задаётся только через `wrangler secret put`.

## Сборка для GitHub Pages

```powershell
dotnet run --project build -- web
```

Результат находится в `artifacts/web/wwwroot`. При публикации приложение не включает локальную копию контента и читает данные из:

```text
https://raw.githubusercontent.com/Pianikova/Pianikova.github.io/main/content/
```

Workflow `.github/workflows/pages.yml` («Publish») запускает этот таргет и деплой на GitHub Pages только по ручному вызову (`workflow_dispatch`) — из вкладки Actions.

## Контент

Настройки формата находятся в `content/settings/site.json`. Текущая версия схемы — `2`, основной язык — английский.

- `content/site/en/site.json` и `content/site/ru/site.json` — главная страница, биография, проекты, пресса и контакты;
- `content/schedule/en/schedule.json` и `content/schedule/ru/schedule.json` — расписание концертов;
- `content/videos/en/videos.json` и `content/videos/ru/videos.json` — видеозаписи выступлений;
- `content/articles` — зарезервировано под статьи (см. выше, пока не используется);
- `content/media` — общие изображения, видео и документы.

Короткие подписи интерфейса — меню, кнопки, статусы и сообщения — используют стандартную локализацию .NET: `src/Pianikova.Web/Resources/Ui.resx` для английского и `Ui.ru.resx` для русского. Редакционный контент в `.resx` не хранится.

Английский и русский тексты физически разделены: одноимённые документы в `en/` и `ru/` — перевод одного материала. Пути к медиа задаются относительно `content`, например `media/images/julia-pianikova-hero-2026-v2.png`.

Перед запуском и публикацией выполняется проверка:

```powershell
dotnet run --project build -- content-check
```

Она проверяет JSON, наличие обоих языков, совпадение системных полей концертов и существование медиафайлов. Та же проверка запускается автоматически на каждый коммит в workflow `.github/workflows/ci.yml` («CI»).

Статус концерта: `announced`, `on_sale`, `sold_out` или `free`. Время хранится в ISO 8601 со смещением, а IANA timezone — отдельным полем.
